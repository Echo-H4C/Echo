# 1. 취약점 정의

웹 애플리케이션에서 응답 헤더나 에러 페이지로 서버의 버전정보나 서버에서 사용중인 프로그래밍 언어 정보가 노출되는 취약점으로, 해당 정보가 노출됨에 따라 공격자의 2차 공격으로 이어질 가능성이 있으므로 노출되지 않도록 조치해야 한다.


# 2. 점검 방법

웹 애플리케이션 이용 시 에러를 발생시키거나, 응답 헤더를 확인하여 취약점 발생 여부를 확인한다.

# 3. 대응방안

* Apache

apache2.conf 또는 httpd.conf 파일 내 아래 지시자 추가 후 서버를 재기동한다.

- 응답 헤더 내 서버 버전 정보 제거 예시
```
...
ServerTokens Prod
ServerSignature Off
...
```

- 사용자 에러 페이지 정의 예시

```
# 예) ErrorDocument 404 /main/error.html
ErrorDocument 404 /main/error.html
ErrorDocument 405 /main/error.html
# 추가로 에러 코드에 따라 에러 페이지를 지정할 수 있음.
```

* Tomcat

server.xml 파일 내 아래 지시자 추가 후 서버 재기동한다.

- 응답 헤더 내 서버 버전 정보 제거 예시

```
# server.xml 파일 내 <Connector> 요소에 아래 지시자 추가 후 서버 재기동
<Connector port="8080" protocol="HTTP/1.1" connectionTimeout="20000" redirectPort="8443" maxParameterCount="1000" server="" />
```

- 에러 페이지 매핑 예시
```
<!-- web.xml -->
<error-page>
  <error-code>404</error-code>
  <location>/errors/404</location>
</error-page>

<error-page>
  <error-code>500</error-code>
  <location>/errors/500</location>
</error-page>

<!-- 모든 예외(최상위) 공통 500 처리 -->
<error-page>
  <exception-type>java.lang.Exception</exception-type>
  <location>/errors/500</location>
</error-page>
```

* Nginx

nginx.conf 파일 내 아래 지시자 추가 후 서버 재기동

- 응답 헤더 내 서버 버전 정보 제거 예시
```
...
http {
  server_tokens off;
}
...
```

- 사용자 에러 페이지 정의 예시 

/etc/nginx/sites-available/default 또는 nginx.conf 파일 내 아래 지시자 추가 후 서버 재기동

```
server {
  listen 80;
  ...
  # 기타 설정
  ...
  error_page 400 401 402 405 /custom_4xx.html;
  # 404 에러 페이지 지정
  error_page 404 /custom_404.html;
  # 500번대 서버 에러 페이지 일괄 지정
  error_page 500 502 503 504 /custom_5xx.html
  # 에러 페이지 파일의 위치 설정 (필요한 경우)
  location = /custom_404.html {
    root /var/www/html; # 또는 사용자 정의 경로
    internal; # 외부에서 직접 URL로 파일에 접근하는 것 방지
  }

  location = /custom_4xx.html {
    root /var/www/html;
    internal;
  }

  location = /custom_5xx.html {
    root /var/www/html;
    internal;
  }
...
}
```

IIS (7.0 이상)

- 응답 헤더

https://learn2you.tistory.com/16

IIS 관리자 메뉴에 접근해서 URL 재작성 기능을 사용한다. IIS 관리자에서 URL 재작성 메뉴에 접근하여 우측 상단의 '규칙 추가' 버튼을 누르고, 아웃바운드 규칙의 '빈 규칙' 버튼을 클릭한다.

이제 아웃바운드 규칙 편집에서 다음과 같이 설정한다.

```
1. 이름 : 관리할 이름을 자유롭게 설정
2. 검색 범위 : 서버 변수
3. 변수 이름 : RESPONSE_SERVER # RESPONSE_ 뒤에 붙는 단어는 응답 헤더이다. 예시) RESPONSE_X-POWERED-BY
4. 패턴 : .*
5. 작업 유형 : 재작성
6. 값 : none 혹은 빈 값으로 두어도 된다.

# 이와 같은 방법으로 RESPONSE_X-POWERED-BY 같이 규칙을 추가하면 여러 헤더의 정보를 숨길 수 있다.
```

- 에러 페이지

https://blog.naver.com/mschoi72/222050038558

IIS 관리자 메뉴에서 오류 페이지(Error Pages) 메뉴에 접근해서 에러 페이지를 설정한다. 에러 코드마다 설정할 수 있으며, 에러 코드를 더블 클릭하여 에러 페이지 설정 메뉴에 접근하여 Execute a URL on this site(한글로 되어 있을 수도 있음) 를 체크하고 아래의 빈 칸에 개발자가 작성한 에러 페이지 URL을 입력한다.

마지막으로 에러 페이지 URL을 변경한 에러 코드를 클릭하고, 우측의 Edit Feature Settings...를 클릭한다. 그리고, 뜨는 창에서 Custom error pages를 클릭하고 확인 버튼을 누른다.
